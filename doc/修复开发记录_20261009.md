- [维护者在 issue #70 的讨论](https://github.com/micromatch/braces/issues/70#issuecomment-5995348316)质疑该公告的攻击前提和实际用途，指出输入长度限制、不接受不可信 glob，以及更广泛的正则资源消耗风险。此争议属于维护者意见，不能等同于公告已撤回或依赖已修复；核对时 GitHub advisory 仍有效、标为 high，且未列已发布修复版本。
- 维护者关于 5,000 层嵌套超过默认 10,000 字符上限的论据，没有直接排除报告者声称的较低层数（compile 约 3,500、expand 约 4,000）异常。这些阈值来自报告者在特定 Node 版本下的结果，本轮未独立复现，不能作为本项目的固定触发阈值。
- 本项目已确认受影响依赖存在于构建/开发链，固定 SHA 的生产镜像检查确认不包含 braces；尚未证明攻击者可控的深层 pattern 能抵达本项目相关 compile/expand 路径。保留告警并继续按实际调用路径评估，不能仅凭维护者反对就标记为误报、安全或已修复，也不能仅凭 advisory 等级认定生产服务可被攻击。

- npm registry 当前稳定 `drizzle-kit` 为 `0.31.11`，其官方 manifest 仍依赖 `@esbuild-kit/esm-loader` 和 `esbuild ^0.25.4`；不能消除 `core-utils` 带入的 `0.18.20`。把该子依赖强制覆盖到 `0.25.x` 会越过 `~0.18.20` 声明，本轮没有这样做，也没有用审计门槛放宽换绿。
- `drizzle-kit@1.0.0-rc.4` 的 manifest 已不包含旧 loader，但它是预发布版本，官方发布记录包含新的 Drizzle Kit / migration 功能和变更。没有对本项目 schema 生成、迁移输出及恢复路径做兼容验收，因此不把 RC 升级认定为安全替代。
- node-forge/braces 等待上游发布有修复的兼容版本，或 Nuxt/Nitro 的稳定兼容依赖链移除相应受影响版本；届时更新锁文件后重跑完整 audit、Studio build/test 与 production image 验证。esbuild 等待 Drizzle Kit 或 loader/core-utils 的稳定受支持版本不再约束到旧 esbuild，或提供已验证的兼容路径；届时必须对 `db:generate` 和隔离数据库迁移回归。以上补丁未发布/兼容性未证实前，不接受通过不匹配 override 消去数字。
- 本轮没有代码或 lockfile 修复可证明安全，故只补充依赖追踪与状态记录，不为此重跑本地测试。上述验证以固定代码基线 `5bf7f36` 为准。PR 继续 OPEN/DRAFT、`NOT_READY_FOR_MERGE`；生产服务不包含当前 Nuxt/node-forge/braces 构建链（该代码基线的 docker-runtime 镜像检查通过），但开发/CI 依赖告警仍然存在。完整审计 JSON 与运行镜像清单仍未交付；此前 artifact 上传被拒后本轮未重试或改走其他渠道。
