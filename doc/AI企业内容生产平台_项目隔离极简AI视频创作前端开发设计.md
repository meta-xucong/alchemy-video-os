# AI企业内容生产平台：项目隔离极简 AI 视频创作前端开发设计

## 1. 文档状态与约束

**状态：前序项目制体验已验收；本轮“唯一生成入口与创作进度投影”已修正失败态新版本入口并完成本地验证，等待审计。** 本文描述 Studio 前端演进的产品和实现边界；不修改当前 `/api/v1` 契约、领域状态、事件或后端路由，也不代表 C09 的外部 Veyra/共享积分授权已解除。

本设计只针对本地默认配置：`LOCAL_AUTH_MODE=dev`、`VIDEO_PROVIDER=mock`、`VEYRA_AUTH_ENABLED=false`。不读取环境文件，不接入真实 Provider、Veyra、VPS 或部署配置。

- 进度只根据公开 `TaskRun.status` 与当前是否已有 Shot 显示；不声称系统已经生成脚本、分镜、提示词推理或任何未实际执行的内部工作。

## 2. 产品方向

### 2.1 目标用户

目标用户是不熟悉分镜、模型参数、队列和媒体工具的企业内容使用者。他们需要把一个模糊的视频想法变成可播放的本地 Mock 视频，并能在稍后回到同一个项目继续调整。

用户的心智模型应当是：**一个项目就是一项相互独立的创作任务。** 例如“秋季新品开箱短片”和“招聘活动预热视频”是两个项目；各自的想法、参考图、分镜、生成状态、失败重试和结果视频都只在所属项目内出现。

### 2.2 目标

- 首屏让用户清楚地新建、进入、重命名或编辑项目；项目之间不互相干扰。
- 进入项目后只要求用户完成四类输入：描述想法、补充少量参考素材、选择清晰可见的视频规格、生成或调整结果。
- 将既有的资产上传、分镜状态、生成命令、SSE 和重试编排为少量清晰动作，不要求用户理解内部 `TaskRun` 或 Provider 生命周期。
- 刷新、重新进入项目或 Worker 恢复后，继续以服务端 `ProjectDetail` 为事实来源恢复当前项目。
- 维持现有 Alchemy 风格的紧凑、低圆角、中文企业工作台语言，但从“三栏运维工作台”收敛为“项目制创作空间”。

### 2.3 非目标

- 不把不同项目的资产、分镜、TaskRun 或视频结果合并到一个“全局素材/任务池”。
- 不在浏览器推断 Provider 状态、轮询 Provider、访问 `/internal/*`、MinIO 管理接口、数据库、Redis 或 Veyra。
- 不引入真实模型选择、价格、额度、余额、扣费、协作审阅、成片编辑、脚本智能体或批量项目。
- 不把创作描述中的数字宣称为隐含模型设置；视频规格只通过可见的受控控件写入 `generation_settings`，不由浏览器编译为 Provider 指令。
- 不把 `ARCHIVED` 称为“已删除”；删除只能调用公开的项目 DELETE API，不能在浏览器本地伪造成功。

## 3. 已有事实与契约边界

### 3.1 当前公开 Project 能力

当前已发布 OpenAPI、Zod 和 Control API 路由只包含以下项目能力：

| 用户意图 | 现有 public API | 当前可实现的前端行为 | 边界 |
| --- | --- | --- | --- |
| 查看项目列表 | `GET /api/v1/projects` | 显示当前 workspace 的项目卡片/列表 | 列表天然受后端 workspace 范围限制 |
| 新建项目 | `POST /api/v1/projects` + `Idempotency-Key` | 以项目名创建并进入返回的项目 | 同 key/同 body 回放；同 key/异 body 为 `409` |
| 进入项目 | `GET /api/v1/projects/:project_id` | 读取唯一项目详情聚合 | 详情含本项目的项目、资产、分镜、绑定和公开 TaskRun 摘要 |
| 修改项目 | `PATCH /api/v1/projects/:project_id` + `Idempotency-Key` | 改名，或使用已定义的 `ACTIVE/ARCHIVED` 状态 | `UpdateProjectCommand` 仅接受 `name` 和/或 `status`；删除另见新文档 |
| 删除项目 | `DELETE /api/v1/projects/:project_id` + `Idempotency-Key` | 输入明确的“删除”确认词后执行服务端软删除 | 返回 `DELETED`；有活动工作时返回 `409 PROJECT_IN_USE`，详情与列表隐藏已删除项目 |

`Project` 的公开字段保持不变；本段关于 `status` 只有 `ACTIVE | ARCHIVED` 是删除功能实现前的历史快照。当前 `Project.status` 还包含服务端软删除态 `DELETED`，创建/更新仍只允许 `ACTIVE | ARCHIVED`，详见《AI企业内容生产平台_项目删除功能开发文档.md》。

### 3.2 项目详情是创作页面的唯一事实

`GET /api/v1/projects/:project_id` 的 `ProjectDetail` 是项目页的唯一服务器事实，包含：

- 当前 `Project`；
- 只属于该 `project_id` 的 `assets`，其中用户参考图为 `IMAGE/USER_UPLOAD`，成功视频为 `VIDEO/GENERATED`；
- 同项目的 `shots` 与 `reference_bindings`；
- 同项目的公开 `task_runs`，不含 Provider、`provider_request_id`、原始 payload、`object_key` 或签名 query。

前端不得自行通过全局任务列表、浏览器缓存或已收到的 SSE 拼出项目详情。任何进入、刷新、生成后或重试后的恢复都重新读取此详情。

### 3.3 当前创作命令映射

| 极简界面动作 | 静默使用的既有 API | 前端不得越过的边界 |
| --- | --- | --- |
| 添加参考图 | `POST /projects/:id/assets/upload-requests` -> 服务端提供的 presigned PUT -> `POST /assets/:id/confirm-upload` | URL/headers 仅留在当次内存；浏览器不提交 object key |
| 保存“想法” | `POST /projects/:id/shots` 或 `PATCH /shots/:id` | 一次项目内创作由一个“当前创作分镜”承载；后端仍允许项目有多个 Shot，前端不删除历史数据 |
| 设置可生成 | `PATCH /shots/:id`，更新为 `READY` | 不把保存分镜与创建任务混为一个后端命令 |
| 生成 | `POST /shots/:id/generations` + `Idempotency-Key` | 只在公开允许的 Shot 状态和无活动 TaskRun 时发起 |
| 重试 | `POST /task-runs/:id/retry` + 新的 `Idempotency-Key` | 只显式重试既有运行；不得重新提交、改变输入快照或重复 Provider submit |
| 视频预览 | `GET /assets/:id/download-url` | 结果 `Asset` 已 READY 后才显示；签名 URL 不持久化 |

当前本地 Mock 生成输入保持已认证的固定最小值（`mock-video-v1`、`1` 秒、`160x90`、`16:9`）。自然语言偏好不能伪造未开放的模型、价格或能力参数。

C09-C 的 Studio 第三步在生成按钮前增加“视频规格”：时长为 `1..15` 秒下拉菜单，清晰度为 `480p/720p` 单选项，画幅为只读 `16:9`。默认值为 `5 秒 / 720p`。这些值通过既有 Shot 保存路径写入受控 `generation_settings.video_settings`，因此同一项目刷新后可恢复，调整后生成新版本时可重新选择；浏览器仍只发出公开 Shot/generation 命令。Mock 继续固定其确定性夹具参数，真实 profile 才将保存值冻结到 TaskRun。

## 4. 项目是唯一创作任务边界

### 4.1 项目生命周期与入口

项目首页只显示当前 workspace 的项目。每个项目条目至少显示项目名、最近更新时间、状态和一条安全摘要；不显示其它项目的资产缩略图、任务错误或视频 URL。

1. **新建项目**：用户输入一个简短名称，例如“春季新品短片”。提交 `POST /projects` 成功后，立即导航到该项目的独立创作页。
2. **进入项目**：由项目卡片、浏览器历史或刷新后的项目 ID 进入。前端先清空旧项目的临时状态，再读取目标 `ProjectDetail`。
3. **重命名或编辑项目**：项目标题旁提供“编辑名称”，提交 `PATCH /projects/:id { name }`。输入为空、重复点击和请求中状态均要被禁用或明确显示。
4. **归档（可选且如实命名）**：仅在产品确有需要时，使用现有 `PATCH { status: "ARCHIVED" }`，文案必须是“归档项目”，不能显示为删除。
5. **删除项目**：项目页先要求输入“删除”确认词，再调用公开 DELETE 命令；服务端只做软删除并保留历史资产，存在活动任务时返回 `PROJECT_IN_USE`。

项目建议使用前端路由 `/projects/:project_id` 表达可刷新、可分享的本地页面位置；该路由只决定随后读取哪个既有公开详情 API，不带授权信息、签名 URL 或项目快照。

### 4.2 项目切换与隔离算法

项目隔离的根由后端 `workspace_id + project_id` 查询和授权保证，前端只负责不污染本地视图。每次选择 `nextProjectId` 时，按以下顺序执行：

1. 立即释放前一项目的 `previewUrl`，关闭媒体 dialog，清除预览资产 ID、待上传文件、上传阶段、分镜草稿、已选参考资产和项目内错误提示。
2. 使前一项目的详情请求失效（`AbortController` 或 request sequence）；只有响应项目 ID 仍等于当前选择时才能写入页面状态。
3. `GET /api/v1/projects/:nextProjectId` 并以完整响应替换当前 `ProjectDetail`；不做数组合并。
4. SSE 连接继续按 workspace 保持，不因项目切换创建另一个项目级连接。收到公开事件后，仅当事件的公开项目归属等于当前项目时才刷新当前详情；非当前项目事件只能更新全局连接状态或未来的安全项目徽标，不能写入当前资产/TaskRun 列表。
5. 浏览器刷新时从路由恢复 `project_id`，再次读详情。路由不可访问、`404` 或 `WORKSPACE_FORBIDDEN` 时清除当前项目 UI，回到项目首页，并显示公共错误文案。

以上规则适用于用户项目和生成产物：任何生成视频也必须从其 `TaskRun.result_asset_id` 和当前项目 detail 读取，不能按 asset ID 在浏览器缓存中跨项目复用。

### 4.3 删除项目的硬性契约缺口（历史，已被新文档 superseded）

本节记录的是删除功能尚未开放时的设计状态。当前实现以《AI企业内容生产平台_项目删除功能开发文档.md》为准；该文档定义了公开 DELETE、软删除、活动工作阻断、幂等回放和显式二次确认，不再适用本节“当前唯一可用选择”的结论。

因此有且只有两种合规实施选择：

| 选择 | 前端行为 | 前置条件 | 当前结论 |
| --- | --- | --- | --- |
| A. 服务端先提供删除能力 | 历史前置条件 | 已由新文档和当前实现覆盖 |
| B. 将删除保留为规划 | 历史保守方案 | 不再作为当前行为 |

不得采用以下替代品：前端从列表本地移除项目、调用 `PATCH ARCHIVED` 后提示“已删除”、删除浏览器缓存后假装成功，或直接请求数据库/对象存储。

旧稿中的确认界面和契约讨论仅保留为历史背景；当前二次确认、活动工作阻断、保留策略和错误语义均以新文档为准。

## 5. 极简项目内创作体验

### 5.1 主任务流

进入项目后，界面围绕一个连续动作组织：

```text
描述想法 -> 添加少量参考素材 -> 说明偏好 -> 生成 -> 调整或重试 -> 保存并预览
```

1. **描述想法**：一个主文本框，提示用户说清人物/产品、场景、主要动作和想传达的感觉。内容映射到 `Shot.prompt`，不是未经声明的 AI 改写结果。
2. **添加少量参考素材**：可跳过。界面推荐 1--3 张图以降低认知负担；现有后端允许最多 8 个 `reference_asset_ids`，超出前端推荐上限的规则需在实施前作为纯 UI 决策测试。
3. **自然语言偏好**：使用短选项和可选补充文本，例如“节奏：舒缓/自然/有力”“画面：产品清晰/氛围优先”。在当前 Mock 阶段只编排为受控 `generation_settings` 或追加到用户可见的 `Shot.prompt`，不展示虚假的模型参数。
4. **生成**：唯一主动作位于第三步。前端先保证当前 Shot 已保存且为 `READY`，再调用既有 generation API。用户只看到“准备画面与节奏”“正在生成视频”“检查成片”“已完成/未完成”等公开状态投影。
5. **调整**：用户更改想法、偏好或参考绑定时，保存分镜；若已有结果，明确提示“本次调整会形成新的生成运行”，并遵守 `TaskRun.input_snapshot` 不可变。
6. **保存与预览**：保存指的是项目/分镜已经在 Control API 持久化，不另造浏览器“草稿事实”。成功成片会固定显示在本项目的“项目成果”区，最新成片默认进入页内播放器；用户可切换查看本项目此前完成的每个版本。每次播放只使用一次短时预览 URL，切换项目、离开页面或刷新后必须重新授权获取。

### 5.2 静默编排原则

单个“生成视频”按钮可以在前端顺序完成已有命令，但每一步仍是独立的公开 API 调用：

```text
必要时保存 Shot -> 必要时 PATCH READY -> POST generation -> 等待 SSE/重新读取详情
```

每个命令使用新的 `Idempotency-Key`；不得把多个 HTTP body 伪装为一次原子 API，也不能因刷新自动重新提交 generation。若保存成功但 READY 或 generation 失败，页面保留已保存创作内容，并给出该步骤的中文可行动错误和明确下一步。

### 5.2.1 唯一生成入口与创作进度投影

“保存想法”和“开始生成视频”是两个用户意图，必须分开：

| 位置 | 用户可见动作 | 实际行为 | 禁止行为 |
| --- | --- | --- | --- |
| 第一步：描述想法 | `保存想法` | 仅创建或更新当前 `Shot`；成功后提示前往第三步开始生成 | 不创建 TaskRun，不显示生成按钮，不把保存称为生成 |
| 第二步：参考图可选 | 上传并确认、选择参考图 | 继续使用现有上传确认与绑定输入 | 不因选择图片自动保存或创建 TaskRun |
| 第三步：生成并查看结果 | `开始生成视频` / `调整后生成新版本` / `重试生成` | 唯一调用现有 `generateVideo()`；它仍顺序保存 Shot、必要时设为 `READY`、再创建 generation | 不拆成新的后端 API，不重复提交，不把重试变成新生成 |

当没有当前运行时，第三步显示“开始生成视频”。当前运行已 `SUCCEEDED` 或 `FAILED` 时，主按钮显示“调整后生成新版本”，并沿用既有保存 Shot -> 必要时 READY -> generation 编排及新的命令幂等键。`FAILED` 时还必须同时提供“重试生成”，它只调用既有 TaskRun 重试接口、复用不可变输入快照；两者不能互相替代。`BILLING_FAILED`、`ABANDONED` 和所有非终态运行不开放新版本主按钮，避免绕过既有计费或运行状态边界。

第三步固定展示以下四段创作进度：

1. `整理创作需求`：尚未创建任务；有已保存 Shot 时显示“已保存，等待开始”，否则提示先描述并保存想法。
2. `准备画面与节奏`：公开状态为 `CREATED`、`QUEUED`、`RUNNING` 或 `RETRY_SCHEDULED`。这是对已经提交的创作请求的用户体验投影，不表示额外生成了脚本、分镜或提示词。
3. `正在生成视频`：公开状态为 `PROCESSING`。
4. `检查成片`：公开状态为 `DOWNLOADING` 或 `BILLING_PENDING`；只表示结果正在经过平台既有的可用性收敛，不暴露存储、扣费或内部工作细节。

终态使用同一进度框架替换状态摘要：`SUCCEEDED` 显示“视频已生成”，`FAILED`、`BILLING_FAILED` 或 `ABANDONED` 显示“本次创作未完成”，并且只提供既有的预览、调整后生成新版本或显式重试动作。映射函数必须集中在纯前端模块中，以便完整覆盖全部公开状态，模板不得自行猜测内部生命周期。

生成命令返回 `202 + TaskRun` 后，Studio 必须立即把该公开 TaskRun 合并到当前项目的内存投影，再进行详情刷新和等待 SSE。生成区在该任务仍为非终态时明确显示“本次创作已提交，正在更新进度”；该任务成为 `SUCCEEDED` 或失败终态后，回执分别显示可预览或可行动的下一步。不得丢弃这份公开响应后只依赖异步刷新，否则本地 Mock 的极短完成时间会让用户误以为按钮没有响应。此投影不新增前端任务真相：刷新、重进项目或收到事件仍以 `GET /projects/:project_id` 的完整响应覆盖。

### 5.3 状态与错误语言

| 后端公开事实 | 项目内中文呈现 | 允许的用户动作 |
| --- | --- | --- |
| 无项目 | “先新建一个项目，开始一项视频创作。” | 新建项目 |
| 无参考素材 | “参考图可选；添加后可帮助统一画面。” | 添加参考图或继续描述 |
| 尚无 `TaskRun`，且无当前 Shot | “整理创作需求” | 描述并保存想法 |
| 尚无 `TaskRun`，已有当前 Shot | “已保存，等待开始” | 修改、添加参考、前往第三步开始生成 |
| `CREATED` / `QUEUED` / `RUNNING` / `RETRY_SCHEDULED` | “准备画面与节奏” | 只读等待；不重复生成 |
| `PROCESSING` | “正在生成视频” | 只读等待；不重复生成 |
| `DOWNLOADING` / `BILLING_PENDING` | “检查成片” | 只读等待；不重复生成 |
| `SUCCEEDED` | “视频已生成” | 预览、调整并生成新版本 |
| `FAILED` | “本次创作未完成” | 编辑当前创作；“重试生成”复用既有任务，或“调整后生成新版本”创建新运行 |
| `BILLING_FAILED` / `ABANDONED` | “本次创作未完成” | 显示当前公开终态与既有允许的后续动作；不以新版本主按钮绕过计费或取消边界 |
| `NOT_FOUND` / `WORKSPACE_FORBIDDEN` | “该项目不可访问或已不存在。” | 返回项目列表 |
| `IDEMPOTENCY_CONFLICT` | “这次操作已经使用了不同内容提交，请刷新后重新操作。” | 刷新后使用新命令 |

错误面板只能使用公开 `code`、`message` 和 `retryable` 的中文归一化结果。严禁显示 Provider 原文、请求 ID、模型内部名、对象 key、签名 URL、Veyra 字段或队列细节。

这里的 `retryable` 只描述当前失败是否适合由系统自动恢复，不决定用户是否可发起既有 `POST /task-runs/:id/retry` 命令。按照既有 TaskRun 状态机，`FAILED -> QUEUED` 是用户显式重试；前端使用新的 Idempotency-Key 调用该公开命令，不创建新的生成任务、不改变 `input_snapshot`，也不直接提交 Provider。

## 6. 信息架构与布局

### 6.1 项目首页

桌面项目首页采用无浮动营销卡的工作区带状布局：左上为“我的项目”和新建动作，主体为项目卡片列表。每张卡片是可进入的项目，不承载跨项目操作。

```text
应用栏：品牌 / 当前工作区 / 服务状态
------------------------------------------------
我的项目                         新建项目
项目卡：名称、最近更新、状态       [进入]
项目卡：名称、最近更新、状态       [进入]
空态：从一个视频想法开始           [新建项目]
```

新建项目在页内弹层或展开表单完成，含项目名称、创建、取消。创建中禁用重复提交；成功后立即进入新项目；失败保留名称和公共错误。

### 6.2 项目创作页

宽屏以主创作区与持续成果展示区并列，采用 Alchemy V3 的项目成果思路，而非将成片藏在临时 dialog 或暴露内部运行面：

```text
项目头部：返回项目 / 项目名 [编辑] / 保存状态 / 更多（归档或受阻的删除说明）
------------------------------------------------------------------------
描述想法 + 自然语言偏好                         项目成果
参考图 + 生成主动作 + 当前公开状态               选中成片播放器
------------------------------------------------------------------------
此前创作版本（可展开）                            成片版本列表与切换动作
```

项目内只突出一个“当前创作分镜”。已有多个 Shot 时，当前分镜按最近编辑或明确选择决定；其余内容放入“创作版本”折叠区。项目成果区则独立依据本项目已成功的公开 `TaskRun.result_asset_id` 与 `VIDEO/GENERATED/READY` 资产投影，按时间倒序展示每份正式成片。它不显示失败任务、处理中任务、参考图、内部 ID 或其它项目资产，避免把后端模型限制强加给非专业用户，也不丢失既有 C04/C06 数据。

### 6.3 移动端

移动端按任务顺序单列：项目头部 -> 描述和偏好 -> 参考素材 -> 生成状态/主按钮 -> 项目成果播放器与版本 -> 历史版本。项目列表是单独页面而非横向塞入创作页；所有主按钮占满可用宽度，图标按钮维持稳定尺寸，文字可换行且不截断关键状态。

参考图媒体预览继续使用全屏 dialog。成片使用项目成果区内的 `<video controls>`，保留可见的项目交付位置；点击其它版本才替换当前播放源。切换项目、返回项目列表、离开页面或关闭参考图 dialog 时释放相应预览 URL；不把 URL 写进路由、localStorage 或截图/日志。

| 层级 | 场景 | 通过条件 |
| --- | --- | --- |
| 静态前端测试 | 路由和请求边界 | 只出现 `/api/v1`；没有 `/internal`、Provider、Veyra、object key、签名 query；删除仅通过公开 `DELETE /projects/:project_id`，不直接操作内部存储 |
| Project API 合同测试 | 创建、改名、归档 | 每个命令有 `Idempotency-Key`，同键回放/冲突遵守既有 API；未把 `ARCHIVED` 文案写成删除 |

| 刷新与恢复 E2E | 项目 A 生成中或已完成时刷新/重启 Worker | 路由恢复 A，重新读取 A 的 detail；不创建第二个 TaskRun 或第二次 submit |

| 生成入口与进度回归 | 保存想法、开始生成、公开状态变化 | 第一步没有生成按钮或 generate emit；第三步是唯一入口；所有公开状态都有中文进度且不泄露内部名称 |

| 删除回归 | 软删除、重放与活动工作阻断 | 名称未匹配不能确认；成功返回 `DELETED` 且列表/详情隐藏；同幂等键重放相同结果；活动 TaskRun/ProductionRun 返回 `409 PROJECT_IN_USE` |
| 响应式验证 | 桌面、平板、`390x844` | 首页与项目页不横向溢出，项目名、状态、主按钮和关闭预览动作可访问 |

## 9. 实施迁移路线

1. **M0，本文设计阶段**：确认项目隔离、删除缺口与当前 public API 映射；不写应用代码。
2. **M1，项目壳层**：实现项目首页、项目路由、创建/进入/改名和切换清理，只复用现有 Project API；先完成 A/B 隔离 E2E。
3. **M2，极简创作编排**：把当前资产、分镜、生成、重试、预览整理为项目内连续流程；保持所有 C04/C06 API 和 TaskRun 语义不变。
4. **M3，删除能力**：后端契约、软删除状态、幂等与活动工作阻断已由《项目删除功能开发文档》定义并实现；后续只补充独立审计证据，不得改为浏览器本地删除或物理级联删除。
5. **M4，后续能力**：待独立章节授权后，再考虑真实 Provider、能力认证、共享积分、Prompt Compiler、企业资料或成片工作流。它们不能与本项目制前端改造绑在同一个变更中。
