# 显式 Doubao 整轨替换与 ProductionRun 来源绑定

版本：`1.0.2`  
状态：`PROPOSED_FOR_INDEPENDENT_DOC_AUDIT`  
日期：`2026-10-04`

## 1. 目的与范围

修复现有音频策略的一个明确缺口：操作者能够选择 Doubao TTS，但现有网页创建命令、ProductionRun 私有快照和 Media Runtime 组合计划之间没有可验证的同一次运行选择凭证；因此 Runtime 无法区分“操作者明确要求用 Doubao 替换整条原生音轨”与“未经授权地把 Provider 原声和独立音频混合”。本任务只实现该显式选择和 source-supported 整轨替换路径。

不新增音频专用公开路由、数据库列、Provider 视频协议、账户/计费行为或第二套 AudioPlan；不改变模型生成画面、分镜、时长、转场、字幕、TTS 文本、音频质量算法或默认 Mock 配置。E12/R01、C12.4/C12.5 的正式状态不因本任务改变。

## 2. 固定来源与行为裁定

固定 OpenMontage commit：`4eab34c5cfcccaa4f1970554928feccce73ee930`。

- `tools/video/video_compose.py::_mux_external_audio` 使用已渲染视频的画面流 `0:v:0` 和外部音频流 `1:a:0` 重新封装；原容器中的音频不被映射。这是整轨替换，不是 overlay、对白分离或 SFX 重分类。
- `tools/audio/audio_mixer.py::AudioMixer._full_mix` 只混合显式传入的 speech/music/SFX 音轨，并对其输出单独重新封装。因此被替换的 Provider 原声不得作为 `_full_mix` 的来源 track。
- `AI企业内容生产平台_自动生成音频与视频匹配正式使用开发文档.md` §0.1、§1.0 已规定 native 默认保留；只有操作者明确选择 `DOUBAO_TTS` 才走替换；未知/缺失仍阻断。

字段语义必须分离：

1. `VideoGenerationInputSnapshot.audio_owner` 继续陈述视频 Provider/profile 的能力或已验证 owner；不得改写为 TTS 选择。
2. 新命令字段 `audio_selection` 陈述本次 ProductionRun 的输出音频选择：`PRESERVE_PROVIDER_AUDIO` 或 `DOUBAO_TTS_REPLACE`。
3. 只有第二个值才授权移除该 ProductionRun 所有源视频音轨；它不代表把源音轨标成对白、环境声或 SFX。

## 3. 冻结的端到端契约

### 3.1 公共命令与默认兼容

在既有版本化 `CreateProductionRunCommand` 增加：

```ts
audio_selection: "PRESERVE_PROVIDER_AUDIO" | "DOUBAO_TTS_REPLACE"
```

省略字段的历史客户端由 schema 归一到 `PRESERVE_PROVIDER_AUDIO`，保持现有默认行为；任何未知值拒绝。DOUBAO 值必须由 Studio 用户选择显式传入，禁止根据 profile、自述、对白标签、DeliveryPlan `voice_mode` 或环境配置推断。

### 3.2 同一 ProductionRun 冻结

Control API 将解析后的选择传给现有 `ProductionRunCommandInput`。Persistence 在创建 ProductionRun 的同一事务内把选择写入现有私有 `production_runs.budget_guard.audio_selection`；其值随不可变 ProductionRun 生命周期保留。幂等请求 hash 自然包含命令字段；同键不同选择必须冲突，重放返回同一 run/选择。不得写入公开 ProductionRun DTO、outbox event、日志或公开 SSE。

Worker 必须由 `production_run_id` 读取该私有冻结事实，不从队列事件携带值、不用当前全局环境替代。历史 run 无字段按 Preserve 兼容；畸形/未知值 fail-closed。

### 3.3 Runtime 内部组合凭证

ALCHMED8 的固定布局没有 audio-selection 字段；不能在旧布局尾部偷塞数据、重解释已有 `audio_owner` 或从轨道标签推断用户选择。故在既有私有 composition carrier 上增加仅含选择的 ALCHMED9 版本，ALCHMED1–8 reader 保持兼容，旧 wire 的选择语义恒为 Preserve。此为平台 provenance 载荷，不是新增 OpenMontage 行为、AudioPlan 或 source feature；此前来源登记中“不新增 ALCHMED9”仅约束当时 E05/S03 的冻结写集，不否定本次经 ADR-0078 授权的独立候选。来源登记必须追加本任务例外指针，不能改写历史接受记录。ALCHMED9 未知/畸形选择拒绝。

DOUBAO 分支必须同时满足：

- 已持久化选择精确为 `DOUBAO_TTS_REPLACE`；
- 在 CreateProductionRun 提交前已存在与所选 DeliveryPlan revision、Storyboard、批准 script revision 绑定的 READY `TimelinePlan`。若只有一个 PRIMARY 窗口且它精确覆盖 `0..target_duration_ms`，可引用一份完整整轨正式 `NarrationAssetVersion`；若有多个 PRIMARY windows，每个窗口必须引用独立正式 `NarrationAssetVersion` 并一一匹配 section 与测量时长。禁止把一条 full-track 资产自动偏移、切片或推导到多个 section。所有正式版本须非样音、`sample_approved=false`、不等于 approval event 的 sample asset，且脚本 hash/版本、section、workspace/project、duration、asset SHA/MIME/size、voice/settings 和现有时间窗校验全部通过；
- 所有被 TimelinePlan 引用的正式版本均由显式 `provider="doubao"` 生成且 provider settings/voice 身份与本次批准事实一致；不得从 Runtime 当前环境或自由文本推断。仅有 canonical text 而没有已批准 formal asset/TimelinePlan 时，在 ProductionRun 创建前 `PREFLIGHT_BLOCKED`，不创建 run/outbox、不启动视频 Provider 或 TTS；
- Composition 只消费上述已持久化的 formal asset bytes，不在合成重试中重新调用 TTS。TTS provider 不匹配、缺失、Piper/unknown，或任一 asset/timeline/hash/provenance 不匹配，均在 ProductionRun 创建前阻断；
- Worker 在编码 Runtime 请求前验证 ProductionRun ID → 冻结 audio_selection → DeliveryPlan/Storyboard → READY TimelinePlan → approved ScriptRevision → NarrationAssetVersion → AUDIO asset ID/SHA/duration 的同 run/同 workspace/project 全链一致。ALCHMED9 只携带 audio_selection；不声称它包含 ProductionRun ID 或 NarrationAssetVersion ID。ALCHMED8 AudioPlan/wire 携带现有 track/asset identity 与时间窗，但版本 ID 仍只在 Worker 前置门校验。

不可仅因选择值就跳过现有 narration/TimelinePlan 校验。不得把样音当正式资产，不得隐式重写 prompt，不得在失败时转回原声或其它 TTS。新 run 的 preflight 必须发生在任何 `production_run.confirmed` event/segment/TaskRun/ProviderAttempt 之前；已存在 DeliveryPlan 的样音审批、正式生成与 TimelinePlan 由现有 narration API 流程完成。

## 4. Runtime 执行规则

1. `PRESERVE_PROVIDER_AUDIO` + Music OFF：沿当前兼容路径不改来源媒体既有音轨；不得自动合成 Doubao。来源音轨不存在时不制造静音/音轨。
2. `PRESERVE_PROVIDER_AUDIO` + Music ON：如果 embedded source audio 的 role 无法按既有 AudioPlan 证明/分离，继续 fail-closed，不生成合成结果；只有现有 OpenMontage source mapping 证明可混的全部轨道才可继续。不借本任务开放叠加。
3. `DOUBAO_TTS_REPLACE`：构造视频时间轴时不把任何输入段的 embedded audio 映射到临时 stitched video（单段及多段一致）；将已验证的 formal Doubao narration asset 与明确 Music 轨交给现有 OpenMontage `_full_mix`。最终 remux 只映射组合视频 `0:v:0` 和 `_full_mix` 输出 `1:a:0`。不得把任何原 MP4 音轨放入 SFX、speech 或其它 mixer tracks。
4. 若选择、wire 版本、formal asset/provider provenance、目标时长或 AudioPlan 事实不匹配，必须在创建 run 时（可提前发现项）或写入成片前 fail-closed。
5. Music OFF 时仍按来源 `_full_mix` 仅输出明确 Doubao narration；Music ON 时使用现有 MUSIC asset/AudioPlan 和 `_full_mix` 行为。不得改变 MusicPlan 的既有语义。

## 6. 验收测试

- command 未提供时归一为 Preserve；旧客户端/ALCHMED1–8 兼容。
- 显式 Doubao selection 被写入 `budget_guard`，响应/event 和结构化错误日志不回显请求体/私有音频事实；相同幂等 key 相同选择稳定 replay，不同选择冲突。
- 同一个 ProductionRun 重启/组合重试仍读取其冻结 selection；不受之后 Studio 选择或全局配置变化影响。Worker 层断言 run/DeliveryPlan/Storyboard/TimelinePlan/script/formal asset version/asset ID/SHA 的 exact identity chain；Runtime wire 只断言其实际携带的 audio_selection、AudioPlan track/asset identity/windows 与对应 bytes，不虚构 version ID/run ID wire 字段。
- Provider/profile `audio_owner=NATIVE_PROVIDER` 与 run `audio_selection=DOUBAO_TTS_REPLACE` 同时保存且不互相覆盖。
- Doubao selection 缺 TimelinePlan、缺同 script revision 的 formal asset、样音复用、provider!=doubao、voice/settings/hash/asset/timing mismatch 时，在创建 ProductionRun/outbox/task/provider attempt 前阻断；正例在 Worker 层证明 DeliveryPlan→TimelinePlan→ScriptRevision→NarrationAssetVersion→run snapshot 的 IDs 一致，并单独验证 Runtime 实际 wire 字段（selection、track/asset ID、window、bytes/hash），不声称 Runtime wire 含 version/run ID。
- Doubao composition 重试读取相同 frozen formal asset identity/hash，不重新调用 TTS；缺失/变更事实 fail-closed。
- Doubao 正常路径不会将源 MP4 音轨映射为 segment AudioPlan、SFX、speech 或 `_full_mix` 输入；画面时长/转场不变；最终封装音轨来自已验证 Doubao 与显式 MUSIC，仅一条 AAC 输出。Full-track 只允许唯一 PRIMARY `0..target` window；多 PRIMARY windows 必须独立正式资产一一对应，禁止自动偏移或切片。
- Preserve + Music OFF 保留原声且不调用 TTS；Preserve + Music ON 在 source role 不可证明时 fail-closed（当前 P6 已有边界），不宣称该组合成功。
- 单段/多段、native embedded audio 存在/不存在、替换选中/未选中、Runtime 错误和重试均覆盖。

测试使用本地构造媒体与 fake/stub Doubao adapter；本任务不调用真实 Provider、TTS、Veyra、网络或部署，不读 `.env.local`。
