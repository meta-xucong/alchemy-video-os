## 1. 用户决定与适用范围

用户于 2026-10-04 明确批准豁免 G02 中因 `multi-agent-dev` Skill/Codex 桌面协作路径偶发问题而无法获得的子 Agent 实际模型/思考强度运行凭证，并说明该问题与 Video 项目本身无关。此为用户对这一项流程证据缺口的明确风险接受。

此例外仅适用于上述 G02 TaskSpec 的 Codex `source_fidelity` 与普通 `audit` 子任务路由元数据缺失，不适用于其他项目、章节、任务、工作流或真实 Provider profile。不得把该决定扩展解释为代码、来源映射、素材、Provider、音视频质量或运行环境门禁的豁免。

## 2. 精确豁免项与保留项

### 豁免项

- G02 的独立代码/来源审查不得仅因 Codex 桌面运行时未暴露实际 model/effort，而被判为不具独立性或拒绝接收其内容结论。
- 对 G02 继续显式记录 `ROUTE_UNVERIFIED`；允许将其作为风险警告，而非本任务代码/来源审计的单独阻断项。不得将其改写为 `PROFILE_VERIFIED`、`EXPLICIT_ROUTE_VERIFIED`、模型/effort 匹配或路由合规。
- `HOOK_UNVERIFIED` 继续独立记录；Hook 不作为此 G02 内容审计的成功凭证或单独阻断项。该处理不代表 Hook 已运行、可用或被证明为官方故障。

### 仍为硬门

1. Source Fidelity 与普通 Audit 必须由不同的独立只读子任务完成；两者必须绑定同一冻结 TaskSpec revision、source mapping、target manifest/diff 和明确的子任务身份。
2. 必须由 Codex 会话记录或等价受信运行记录核实 child thread ID、启动/派发关联和终态完成事件。缺少 child identity 或 terminal lifecycle 时，独立性不成立，仍须 `HOLD`。
3. Source Fidelity 必须返回完整、可复核、同一 revision 绑定的正式 `SourceFidelityReceipt: PASS`；普通 Audit 必须另有正式 `AuditReceipt: PASS`。历史评论、摘要、主会话转述或自我声明不能替代收据。
4. 若之后实际观察到模型/effort 与请求不一致、子任务身份冲突、父会话过早终止或其他运行异常，本豁免不适用；受影响审计立即 `HOLD` 并重新审查。
5. 不得宣称 Codex skill 路由健康、模型档位正确、只读 sandbox 已验证，或将所请求档位写作实际档位。
