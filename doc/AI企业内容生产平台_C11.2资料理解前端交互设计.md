# C11.2：资料理解前端交互设计

状态：`IN_PROGRESS`

## 1. 产品目标

Studio 面向没有制作经验的企业用户。用户只需要创建项目、写下想法、上传参考图或项目资料、选择时长/清晰度/风格，然后点击一次“开始生成视频”。资料理解、事实选择、剧本、分镜、镜头编排和素材约束均由后台处理。

本设计不把 Markdown、知识块、向量、Chunk、检索分数、Prompt、模型、队列、Worker、Provider、对象存储或人工编排步骤显示给用户。它不新增“先分析再生成”“确认分镜”“选择知识库”等工程式主流程。

## 2. 项目页的资料区域

保留现有紧凑工作台的单一输入框和唯一生成入口。在左侧创作区的“参考图与项目资料”中，每份资料只显示文件名、一个易懂状态和最少操作：

| 状态 | 用户看到的文字 | 可用动作 |
| --- | --- | --- |
| 上传后 | `正在整理` | 无 |
| Markdown 转换完成、正在理解 | `正在理解项目内容` | 无 |
| 已理解且可使用 | `已准备好用于这次创作` | `查看要点`、`本次不采用` |
| 仅部分可读 | `已准备好，部分图表需要补充` | `查看要点`、`本次不采用` |
| 整理/理解失败 | `这份资料暂时无法使用` | `重新整理` 或 `重新理解` |

资料一旦达到 `READY`，默认采用，符合“上传即会被使用”的用户心智。用户可主动选择“本次不采用”，该选择只影响下一次新建 CreativeBrief，不改原始资料、不删除知识结果，也不影响历史成片。重新进入项目时，默认状态从最新 CreativeBrief 的用户来源恢复，而不是从生成片段、交接帧或其他 `DERIVED` Asset 反推。

## 3. 资料要点查看

“查看要点”打开轻量抽屉或页面内展开区，不弹出工程配置窗口。内容按用户语言呈现：

```text
这份资料会帮助 AI 保持以下内容一致
- 项目定位
- 主要卖点
- 目标人群
- 场景与品牌风格

有 1 项内容需要补充确认
```

用户可查看短句式项目要点及“来自：第 N 页 / 某章节”的标签。不得展示整份 Markdown、未处理的资料正文、模型推理、检索分数、事实 hash、对象 key、下载签名或内部错误。

若发现与本次创作相关的明确冲突，抽屉只提出必要的自然语言确认，例如“资料中出现两种不同的开盘时间，请确认本片采用哪一项”。未确认前，该结论不进入视频脚本；其他无冲突内容仍可由后台继续准备。对于无法自动读取的图表，提示用户上传对应图片或在主输入框补一句关键信息，不要求理解 OCR 或解析器。

## 4. 一键生成的行为

主按钮仍是项目页唯一的生成命令：

```text
开始生成视频
  -> 理解创作需求
  -> 准备视频内容
  -> 生成视频
  -> 整理成片
```

- 选中的资料仍在理解时，主按钮禁用，并在按钮附近显示“正在理解项目资料，完成后即可开始”。
- 选中的资料已失败时，主按钮保持禁用，显示“有资料暂时无法使用”；用户可在资料卡执行唯一的重试动作，或选择“本次不采用”。
- 资料为 `PARTIAL` 但没有与本次相关的冲突时，主按钮可用；后台只使用已确认的文字事实，前端说明“会结合已读取的项目内容”。
- 已解决冲突或用户主动不采用该资料后，创建新的不可变 CreativeBrief；不会修改历史版本、自动覆盖成片或重复创建制作任务。

前端在点击后只调用现有的 CreativeBrief -> Plan -> Storyboard -> ProductionRun 控制面编排。资料理解状态来自公开 DTO/SSE；页面不得直接调用任何 Runtime、检索服务、Worker 或 Provider。

## 5. 布局与响应式约束

桌面端“参考图与项目资料”保持一个无嵌套卡片的素材区域：图片横向缩略图在前，资料行在后；“查看要点”只在用户点击时展开，不能挤压或遮挡右侧成片区与镜头片段。移动端依次显示输入、素材、生成、成果；资料要点展开后在自身区域内换行，不能覆盖成片播放器或造成横向滚动。

状态使用文字和图标共同表达，不能只依赖颜色；操作按钮使用重试、关闭/取消采用等熟悉图标并带 tooltip。所有展示名称、摘要和来源标签按容器换行，长 PPT 文件名不得撑破布局。

## 6. 前端状态与测试

前端仅保存公开、项目范围内的数据：资料 ID、用户是否采用、理解状态、质量级别、安全摘要/事实分类、是否存在待确认项。切换项目必须清空上一个项目的资料要点与选择；SSE 更新只能合并当前项目，不能刷新整页或使已有成片自动播放。

必须覆盖：

1. 新上传 PPT 的 `正在整理 -> 正在理解 -> 已准备好` 状态序列与刷新恢复。
2. 成功资料默认采用，用户“本次不采用”后生成命令不带该 source asset；下次新项目资料仍默认采用。
3. `PARTIAL` 和冲突提示为中文且不泄露 Markdown/Provider/队列字段；冲突事实在未确认前不能进入生成命令。
4. 资料理解失败后的显式重试；重试不影响参考图选择、已有成片或其他项目。
5. 一键生成保持唯一；没有分析、检索、剧本、分镜或知识库按钮。
6. 390x844 与桌面布局中资料要点、成片播放器和“查看镜头片段”不重叠，SSE 不造成整页刷新或自动播放。

本设计依赖 `AI企业内容生产平台_C11.2资料理解与按段事实包后端开发设计.md` 的公开 DTO、错误码和状态机；前端不得自行推断资料是否已经可用于视频创作。

> **2026-09-01 当前音频口径**：资料理解前端不要求用户上传旁白/样音；自动视频音频由 Provider 原生或显式 Doubao 服务端路径产生。本文历史的 Mock/外部调用限制仍约束本章实现，不新增音频上传控件、旁路 TTS 或公开协议。
