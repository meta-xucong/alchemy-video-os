# 契约、兼容和冲突裁定

版本：`1.1.0`　状态：`DOC_AUDIT_PASS_WITH_EXECUTION_BLOCKERS`（2026-10-02 Main 冻结 P4/P6 TaskSpec 1.1.0；代码审计尚待完成）

## 1. 适用硬规则

1. 原仓库具体代码、文档和测试是其行为的事实标准；平台新设计、便利性、历史实现、测试绿灯都不能静默覆盖它。
2. 多源仓库先确定每个操作/字段的唯一语义 owner；不同源语义分开映射，不能混成第三套算法。
3. 平台薄壳只处理权限、workspace、DTO serialization、存储、队列、幂等、错误、安全和观测，不更改来源内容/媒体含义。
4. 不新增自造阈值、时长规则、自然语言解析、评分、回退、强行补齐、隐式默认、自动选择、变量改名或 parallel algorithm；只有现有来源/contract 明确需要且本包对应 TaskSpec 列入的变化才可以做。
5. 每一新字段/变量/方法/分支/依赖都要回答：来自哪个 source/contract、谁消费、行为正反例是什么、为何现有变量不能复用。答不出就不加。
6. source gap、profile 不明、冲突、未知格式、未知 wire、无法验证实际 owner 均 fail-closed。

## 2. 公共契约和数据兼容冻结

默认不修改：

- Public HTTP Request/Response DTO、OpenAPI、事件 envelope、SSE。
- Domain entity/state transition/数据库 schema、migration、ID format。
- Provider Video Generation Request 和 Grok/Sub2API wire 参数。
- `MusicPlan { AUTO | MANUAL | OFF }` 的 public 形状与项目级所有权。
- ALCHMED8 格式、ALCHMED1–7 的既有解码兼容。
- C10 的 Document/Conversion/DocumentMarkdownArtifact 数据模型和六种 MIME。

允许的第一选择是沿现有内部字段做纯投影、source mapper 和 validator 修复。如果 source-faithful 行为必须增加/调整契约：

1. 停止当前 TaskSpec，不改代码。
2. 输出最小 ADR，逐字段列出来源字段/符号、平台语义、迁移和旧版本读取/写入行为、权限/脱敏、公开暴露面、事件兼容、测试。
3. Main 核对本文件上位契约并取得用户授权。
4. 新建 revision 的 TaskSpec/允许文件清单，然后重新开始 writer work。

任何新增 public field、DB field、event、enum、wire 或表都不得由执行者在原任务中“顺手补”。

## 4. 短时长路径的精确 gate（实现前必须满足）

执行者不得把 provider_capability.min_duration_seconds 作为在任何来源模式上都可覆盖 Huobao 语义的充分证明。短时长专案要先通过如下清单：

1. 被执行的是确定的 production planner，不是 Mock、deterministic fallback 或 unknown Provider。
2. 当前 profile 的 source provenance 精确指向固定 OpenMontage/Grok duration 事实。
3. 输入的 1–7 秒目标被归类为 source-supported provider segment，不冒充标准 Huobao storyboard paragraph；其内部必须满足实际源路径明示的子镜头/时间规则。
4. mock/non-Grok/unknown/缺失 profile 的 1–7 反例在 canonicalization 前被拒绝。
5. 短时长单段Provider规划最小优化开发文档从 READY_FOR_AUDIT 经独立 Source Fidelity 和普通 Audit 后再标状态。
6. 若语义层无法区分 StoryboardShotSpec 与 Provider segment，本包不允许执行者靠新增字段解决；交 Main 提交最小 ADR/用户确认。

## 5. MusicPlan 与 full_mix invariants

对任一被接受的本地 ProductionRun：

- AUTO/MANUAL 只选择/引用一条 MUSIC Asset，窗口精确覆盖 0..target_duration_ms，asset identity 稳定；OFF 不生成平台 MUSIC track。
- 本轮不做按 video segment 换曲/补歌/循环/截断/淡变算法。上游 OpenMontage 专门的 segmented window operation 不应被误用来满足“全片一首歌”。
- AUTO 选择策略仍是已授权平台扩展；其 query/token/content ranking 不属于 OpenMontage Source Fidelity 结论。
- 全片曲目用于 _full_mix 时，gain/fade/duration/role 都映射到源接受的 track shape；实际音频仍需独立技术和人工验证。
- 只有有独立来源载荷证明的 track 才映射到 OpenMontage `speech`/`music`/`sfx`。不得按 Provider owner 名称推断 MP4 混合音轨的内容角色；不得从“音乐与视频同时存在”推出“旁白已 duck”。
- music_applied telemetry 不得写成 music_mix_verified 或 acoustic QC success。

### 5.1 2026-10-02 P6 role/source 冻结补充

- `ALCHMED8` 仅表明输入含完整 AudioPlan，不是 source-role 证明。source video 的嵌入音轨可能是混合成品；`PROVIDER_DIALOGUE` 也不证明音轨仅含独立对白。
- 允许映射：独立平台 narration bytes → OpenMontage `speech`；独立 MUSIC asset bytes → `music`；独立且来源语义明确的 SFX bytes → `sfx`。当前 TaskSpec 没有授权从 Provider MP4 推导任何一种独立角色。
- native-only + MusicPlan OFF 保持当前逐段音轨保留路径，不强行调用 `_full_mix`。当 source MP4 有音轨且请求同时混入 narration/music/SFX payload，而该 source 音轨没有可证明、可分离的 source role/payload 时，composition 必须 fail-closed，不产生成功 artifact；不得把完整 MP4 音轨打包为 SFX，也不得静默调用历史自制 mixer。
- 以上只收窄 P6 的来源映射和验收，不改 ALCHMED wire、owner enum、Worker/API 或历史 ALCHMED1–7 读取行为。

### 5.2 2026-10-04 显式整轨替换来源裁定（候选）

- OpenMontage `video_compose.py::_mux_external_audio` 已证明显式外部音频采用“原视频画面 + 外部音频”的 remux 替换语义。用户授权的同一 ProductionRun `audio_selection=DOUBAO_TTS_REPLACE` 是执行该既有来源操作的明确控制事实，不是来源 role 识别证据。
- 替换路径必须在单/多段 stitch 阶段完全不映射 embedded source audio；只把同 run 校验的 Doubao narration/MUSIC 字节交给 `_full_mix`，再只映射视频和 `_full_mix` 输出。不得将原 MP4 标为 SFX、speech、dialogue，也不得把 `audio_owner` 改成 TTS。
- 未选中替换、历史缺字段、owner/provenance 错配、非 Doubao adapter 或音频事实缺失时仍遵守 5.1 fail-closed/Preserve 规则。ALCHMED9 只运输用户已经冻结的选择；marker 本身不能证明用户选择或 TTS 事实。
- 本裁定仅在 ADR-0078 和对应 TaskSpec 独立审计 PASS 后生效；不撤销旧版 P6 已证实的“无显式选择不得把 source 音轨与独立音频混合”结论。

## 6. 新变量/字段/方法审计规则

新增 symbol 只允许来自已解锁的 TaskSpec，并须满足：

1. 对应 SF-ID、来源文件/符号/行为测试可写入代码或 evidence；
2. 不是现有同语义值、字段或 helper 的重复表示；
3. 不引入第二套 source/default、平行 API、兼容 shim、alias 或中间缓存；
4. name、unit、null/absent semantics 均与 source/contract 一致；
5. 有正例、负例、跨路径一致性测试；
6. 审计员可从冻结 diff 识别其消费者。

“只为测试好写”“以后也许要用”“上游看起来如此”不是新增变量/方法的理由。不可避免但不在批准清单里的 symbol 先停止，主控修订 TaskSpec。
