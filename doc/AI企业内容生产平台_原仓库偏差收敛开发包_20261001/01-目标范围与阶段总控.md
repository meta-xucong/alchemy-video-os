# 目标范围与阶段总控

版本：`1.0.0`　状态：`DOC_AUDIT_PASS_WITH_EXECUTION_BLOCKERS`

当前门状态（2026-10-02）：`P0_BASELINE_PASS`、`P1_DOC_GATE_PASS`；G02 v1.0.13 P0 source/target refreeze 的 97 行 manifest SHA-256 为 7a25433eb5f2be4fa6d0f618b3d301d79f91e377375622eab7e5b7fe8f48b0eb，P0 后 00–07 文档 hash/status binding 待独立复核。此处只表示基线与文档/状态账本纠偏通过；P2-S/P2-T/P3-P、G02 项目新规划和真实 Provider 仍按各自门禁阻断。

## 1. 本工程只解决什么

依据冻结上游源码，修复或明确隔离以下问题：

1. G02 Semantic Director 生产路径对 Huobao/Seedance 规则的要求和验证不完整，Mock 与真实路径不能混为一谈。
2. Huobao 子镜头标记和 3 秒行只做可选/局部检查，不能证明段落内部时序已完整覆盖。
3. 用户参考资产的 `usage` 事实未全部从 semantic projection 传递到最终视频 Prompt。
4. OpenMontage `_full_mix` 的 MUSIC 轨默认 fade 参数在主路径的 composition→track 映射中丢失。
5. native/source 音轨不能仅凭 owner 名称映成 OpenMontage SFX；来源 sidechain 只认 speech/primary，现有声明不得夸大为已 duck。
6. MarkItDown C10 六种已承诺格式与当前运行锁文件中的可选依赖不一致。
7. 旧版 ALCHMED mixer、OpenMontage 其他已实现适配和未接生产的工具能力需要准确区分，避免新路径误用或文档过度宣称。
8. G02、C10、E05 和短时长专项的文档状态互相冲突；同时冻结的 Sub2API/Alchemy 参考基线不一致。

本工程不是对全部历史章节重做，也不是把一切 `PARTIAL` 一律补成“功能完成”。只有属于当前合同与实际生产路径、且能由冻结来源精确证明的行为才可实现；其余要明确 `DEFERRED`、`UNAVAILABLE`、`BLOCKED` 或 `SOURCE_DECISION_REQUIRED`。

## 2. 范围边界

### 纳入

- G02 Semantic Director 的真实 production path、source canonicalizer、reference projection 与 Prompt Compiler。
- Huobao `storyboard-breaker` 与 `prompt-generator/video-prompt` 当前被 Production/G02 消费的规则。
- Seedance Prompt/ref/sound guidance 当前在项目复用矩阵中声明要吸收的部分；只校验其确实落到真实使用路径，不激活 Seedance Provider。
- OpenMontage `_full_mix` 的音乐轨映射和 sidechain 语义；只有 exact source-role/payload mapping 的轨道进入 `_full_mix`。native-only 且 MusicPlan OFF 保留现有音轨路径；需与 MIXED 角色输入混音但角色不能证明时 fail-closed；旧 ALCHMED 兼容路径隔离；已存在 Adapter 未接 Worker 的状态核实。
- MarkItDown 既有 C10 allowlist 的实际依赖完整性。
- 此前资料包列明的审计记录/映射台账/来源登记状态更新。
- 对当前脏工作树限额和配置改动做兼容性风险分类，不将其当成来源偏差，也不擅自扩充本轮改动。

### 明确不纳入

- 不修改真实 Provider 配置、认证、Grok/Sonnet/Pixabay/TTS/Veyra调用、计费、账号、密钥、生产数据库、VPS、DNS、TLS 或部署；此前单次 Sonnet/最多三次 Grok 且因额度缺失而 `REAL_PROVIDER_BLOCKED` 是旧授权快照。仅当前 G02 TaskSpec 按 `00` §9 的最新 supersession 获得不设次数/金额上限、首个完整有效视频即停的明确授权；当前仍因代码、认证、source/audit 和新规划等技术门而不得调用。
- 当前不生成/购买媒体，不读写用户视频/音频/资产库，不做真实成片听感验收；唯一窄例外是 G02 TaskSpec 中冻结的既有护肤项目，须先通过其全部非额度技术门，再按 `00` §9 执行。此任务额度上限已被用户明确取消，不再以 cap 缺失阻断。
- 不实现 Seedance Provider、视频编辑/延长/多模态能力、HyperFrames 完整渲染、语义视觉 QC、全套 TTS registry 或字幕 Studio。
- 不实现 OpenMontage `segmented_music` 生产 route 来替代项目级完整 MUSIC 轨。当前 MusicPlan 设计明确是一条覆盖全片的轨；分段音乐是来源的另一个操作，除非新任务明确要求，不得接入此路径。
- 不重构 Artifact 数据库、全平台 DTO、工具注册体系或公开 API；先补来源等价映射/冲突证据，只有新的 ADR 明确授权时才能扩展。
- 不格式化、升级无关依赖、重命名目录/文件、移动工作区已有改动或回写历史 migrations。

## 3. 执行治理

- Main 控制用户目标、范围、来源锁、任务顺序、纠偏、集成和对外报告。
- 全程最多一个 write-capable Execute Agent；Source Fidelity 和 Audit 均独立、只读、不得自修自批。
- Think 只用于本文件标成 `D1` 的来源冲突；思考结论只能提出可证选项，不得替代原仓库或用户授权。
- 文件 owner 逐任务指定；任务之间不能并行写入有交叠的目标文件。
- 每个 writer 交付前冻结目标 diff/tree；Source Fidelity 必须对同版本 source matrix/hash 复核；普通 Audit 再独立复核 diff、测试和项目边界。
- 任一来源文件/commit/hash、输入事实或现行合同拿不到时，只暂停受影响任务并写 `INSUFFICIENT_EVIDENCE`；不能为了推进而发明替代算法。

## 6. 每个阶段的固定停机条件

以下任一项出现，停止相关路径、冻结当前版并记录证据：

1. 目标目录外的文件需要改动，或遇到工作区已有差异与任务 patch 重叠且不能无损叠加。
2. 需要增加公共 API、数据库字段、event、Provider wire、新识别字段、行业特例、评分、阈值、自动回退或新的算法才能继续。
3. Source/target 对同一操作语义冲突，且矩阵/用户要求没有唯一裁定。
4. 需要依赖未冻结 Sub2API/Alchemy/MCP 源文件或不完整 profile。
5. 认证表面、Runtime input 或 provider route 不同于 frozen version。
6. 负例没有在进入外部命令/写库/Provider 前 fail-closed。
7. 需要真实 Provider、网络、Veyra、媒体处理服务、VPS 或生产数据来证明本地改动。
8. Source Fidelity/Audit 结论为非 PASS、版本不一致或 runtime provenance 缺失。

禁止“先实现再问”“临时改阈值”“跳过失败测试”“把缺证据写成 deferred 后宣称 PASS”。
