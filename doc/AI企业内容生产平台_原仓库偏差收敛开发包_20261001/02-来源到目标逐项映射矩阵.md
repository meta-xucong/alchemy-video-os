# 来源到目标逐项映射矩阵

版本：`1.0.0`　状态：`DOC_AUDIT_PASS`

## 1. 使用规则

以下每个 `SF-ID` 是一个行为映射单元。执行专员必须针对冻结 commit 和冻结 target revision 复核，不可仅按本表摘要改代码。状态列是本资料包建立时的**待整改/待核实状态**，不是既有章节验收结果。

`CONFIRMED_GAP` 表示代码/测试能证明缺口；`SOURCE_CONFLICT_HOLD` 表示不得直接实现；`PARTIAL_BY_DESIGN`、`DEFERRED` 不是 bug，除非当前项目合同声称该功能已完成/可用；`REFERENCE_UNVERIFIED` 不得给 Source Fidelity PASS。

## 2. Huobao 与 Semantic Director

### `SF-HB-01` 段时长：Huobao 分镜段 vs Provider 接受时长

- **来源：** Huobao `storyboard-breaker/SKILL.md` 固定 commit，正式段落 8–15 秒；OpenMontage Grok `tools/video/grok_video.py::GrokVideo` 的 Provider 输入时长可为整数 1–15 秒。
- **目标：** `apps/workflow-worker/src/semantic-director-canonicalizer.ts::validateSemanticSegmentBoundaries`；`packages/contracts/src/semantic-raw-plan.ts`；`packages/creative-planning/src/semantic-director.ts`；`doc/AI企业内容生产平台_短时长单段Provider规划最小优化开发文档.md`。
- **现状：** 生产校验在 target <8 时用当前 `provider_capability.min_duration_seconds` 作为下限，短时长文档要求仅在已解析 Grok profile 使用 1–15；该短时长专项当前写为 `READY_FOR_AUDIT`，没有 `ACCEPTED` 证明。历史测试覆盖 1/6/7 接受。
- **分类：** `SOURCE_CONFLICT_HOLD`，不是可以直接“统统改回 8 秒”的已确认 bug，也不是已接受的通用例外。
- **实施裁定：** source audit 必须证明运行路径中的 `provider_capability` 是准确解析且唯一映射到上述 Grok source profile；1–7 仅可作为精确 Provider 单段目标，不得被表述为 Huobao 正式故事段。Mock、Unknown、profile 未解析路径必须保留 Huobao 8–15 和 fail-closed。若当前 contract 无法区分两种对象语义，则停在此行，不加新公开字段、不猜兼容策略，交 Main/用户裁定。
- **验收证据：** 1、6、7 秒边界的 profile 正负例；Mock/unknown/non-Grok 拒绝例；每例检查精确 profile/source receipt。现有 `READY_FOR_AUDIT` 文档不能自己批准自己。

### `SF-HB-02` 正式分镜结构化子镜头和场景归属

- **来源：** `storyboard-breaker/SKILL.md`：正式段落一个 scene、2–4 个子镜头、每个子镜头 2–6 秒；scene/character/prop 绑定使用读到的既有事实，不得创造 ID。
- **目标：** `SemanticSegmentDecision` 和 `apps/workflow-worker/src/semantic-execution-service.ts` 的 `compileSegment`/ShotSpec 建构；`packages/contracts/src/semantic-raw-plan.ts`；`apps/workflow-worker/src/semantic-director-canonicalizer.ts`。
- **现状：** 当前 G02 决策主要使用自然语言 `visual_decision`；子镜头标记若存在才检查 2–4。目标 `CanonicalSourceBundleSchema`（`packages/contracts/src/semantic-provenance.ts::CanonicalSourceBundleSchema`）包含 `version`、source text/hash、style preferences、documents、references、user decisions、provider capability 和 target duration；reference source 只有 asset identity/hash/MIME/position/可选 role、usage、objective description。它没有结构化 `scene_id`、`character_ids`、`prop_ids` 或逐镜头归属；raw plan 同样没有这些字段。自然语言、reference role 或模型输出不得替代这些事实。
- **分类：** `BLOCKED_SOURCE_CONTRACT_INSUFFICIENT`。可以确认当前目标契约不能证明来源要求的结构化绑定；实际输出缺陷仍为 `OUTPUT_UNVERIFIED`。
- **允许实施：** 当前不得实现 scene/character/prop 绑定、补字段或增加对应正向测试。仅可保留已存在的 asset/reference identity 与现有校验；这不等价于满足本来源规则。
- **解锁条件：** 主控必须先逐字段证明来源事实、当前领域/API契约兼容性、私有或公开字段边界、旧数据兼容、唯一 owner 和 consumer；若需要字段/状态/schema 变化，先完成 ADR、契约文档修订及用户批准，再新建带精确文件和测试列表的 TaskSpec。缺其中任一项就保持阻断，不从自由文本推断 ID/关系。

### `SF-HB-03` 子镜头 marker 数量、范围和全段连续覆盖

- **来源：** Huobao `prompt-generator/video-prompt/SKILL.md`：分镜段落总时长除以 3 秒向上取整生成时间行；时间范围总和覆盖完整段落；每个 `【镜头N】` 映射 1–2 个连续 3 秒段，顺序一致、不遗漏、不合并、不新增子镜头；最后一行按源示例/规则覆盖真实余数，不额外添加任务。
- **目标：** `semantic-director-contract-surface.ts::directorSystemPrompt`；`semantic-director-canonicalizer.ts::validateSemanticSegmentBoundaries`；其 fixture 与 `semantic-director-canonicalizer.test.ts`。
- **现状：** 校验只对存在的 marker 检查数量，对存在的 `n-m秒` 检查区间长度 2–6 秒；没有要求时间范围从 0 开始、连续无交叠或总长等于 segment duration。测试允许 8 秒只写 0–3 和 3–6。
- **分类：** `CONFIRMED_GAP`。
- **实施行为：** 对当前明确使用 Huobao video-prompt 规则的 G02 production path，契约与 validator 必须对 required marker/time rows 定义同一个格式；按源定义的 3 秒格、最后不足 3 秒余数、镜头 marker 顺序、一对多限制、起点/终点和无重叠/无空隙作显式断言。不得将行扩成新 Provider tasks。简单单动作的 Seedance 4–15 秒模式不强加时间戳；若 G02 同时消费两个 source mode，必须从现有显式 route/source facts 得出所用规则，否则停在 `SOURCE_DECISION_REQUIRED`。
- **回归证据：** 缺 marker、序号重复/跳号、非零起点、空隙、重叠、越过 duration、少覆盖、余数错误、镜头顺序不一致均须在 Provider submit 前失败；最小/最大合法段和 source example 正例通过。

- **认证：** Prompt/schema/response mode 参与 semantic certification surface hash；任何变化都必须生成新 hash，并按现行 G02 专项文档重新过对应 fixture gate。不得用旧 profile 或旧认证结果放行。

## 4. OpenMontage 音频与运行时能力

### `SF-OM-01` 项目级全片 MusicPlan 必须是一条 MUSIC 轨

- **来源：** 项目级 MusicPlan 最新专项文档规定 `AUTO/MANUAL` 成功选择后只有一条 `0..target_duration_ms` MUSIC 轨；`OFF` 无平台 MUSIC 轨；不按视频 segment 分别挑 BGM。
- **目标：** `packages/persistence/src/production-repository.ts` 构造 plan；`apps/production-worker/src/media-service.ts` 编码 Runtime 输入；`services/media-runtime/runtime.py::compose_video_bundle`；`_full_mix`。
- **分类：** 现行架构约束，保留为本轮不变量。
- **实施行为：** 对同一 ProductionRun 逐层验证唯一 MusicTrack、start=0、end=target duration、相同 asset identity、不因片段边界换曲。`music_applied` 只能作为 asset-presence telemetry，不作为试听/QC/覆盖成功证明。
- **边界：** `OpenMontage::_segmented_music` 是独立的 segment-window operation；其 adapter 未接 production route 不构成这条单一全片轨的 bug。不得为了“使 helper 有用”把其接入本工程。

### `SF-OM-02` 默认 MUSIC fade 由 composition 错落在来源不消费的全局字段

- **来源：** `audio_mixer.py::_track_filters/_full_mix` 消费每条 track 的 `fade_in_seconds/fade_out_seconds`；来源 `_full_mix` 没有独立全局 fade 语义。
- **目标：** `packages/persistence/src/production-repository.ts` MUSIC AudioPlan track 与 `music_mix`；`services/media-runtime/runtime.py::compose_video_bundle` 中 `music_input` 映射；`services/media-runtime/adapters/openmontage_audio/full_mix.py`。
- **现状：** 默认 1500/2500ms 放入 composition `music_mix`；所选 MUSIC track 未携带对应 fade；ALCHMED8 full_mix mapper 只取 track 字段；legacy fallback 读取 composition 字段。
- **分类：** `CONFIRMED_GAP`（主 full_mix 路径）。
- **实施行为：** 在 composition→来源 track mapper 中：track 明确给出的非空值优先；字段 absent 时只把当前 MusicPlan 同一轨既有的全局默认 fade 转成该 track 的来源字段；显式 `0` 保持 no-fade 语义。当前 schema 对该字段使用 `.optional()` 而非 `.nullable()`，所以输入 `null` 应在 schema 边界被拒绝，不得传给 mapper 或当成 absent/default。不要把 source track filters 算法复制到第二处。
- **回归证据：** 真实 Persistence output 经 Runtime 的 fake FFmpeg graph 能看到 source track 的 fade-in/out；独立 track override、明确无 fade、其他 speech/SFX track 不误加 fade。

### `SF-OM-03` native Provider 音轨在 full_mix 中作为 SFX，不能触发 narration sidechain

- **来源：** `_full_mix` 只在 `speech/primary` 与 `music/secondary` 同时存在并启用 duck 时建立 sidechain；SFX 在 speech+music premix 后加入。
- **目标：** Persistence AudioPlan ownership；Runtime source audio track `role` projection；`full_mix.py` 与 Runtime call graph。
- **现状：** native/provider 混合音轨映为 `sfx`，音乐 track 上的 duck flag 无 speech key 时不会压低音乐。
- **分类：** `SOURCE_BEHAVIOR_CONDITION`（代码符合来源角色行为），但文档和可观察状态存在 overclaim 风险。
- **实施行为：** 维持 native track 原有 owner/role、不拆音、不改名；对 native+MUSIC 组合不宣称“音乐被对白 duck”。若有明确 PLATFORM_NARRATION speech track，才按来源 branch 验证 duck。不能为达到产品审美自行音频分离或用整段 native track 假扮 speech。
- **测试：** speech+music -> sidechain；sfx+music only -> simple source mix/no sidechain；sfx+speech+music -> sidechain 由 speech key 控制且 SFX 按源顺序加入；保留 audio owner。

### `SF-OM-04` 自制 legacy mixer 的版本兼容隔离

- **来源：** OpenMontage `_full_mix` 固定 commit；目标 `runtime.py::_mix_music_track` 是历史兼容路径，不是该来源符号的等价实现。
