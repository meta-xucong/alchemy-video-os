# C11.4 关键对象连续性与视觉道具锁开发设计

> **2026-09-01 当前音频口径**：本章只处理视觉对象锁。自动旁白不要求用户上传 spoken audio；音频 owner/真实对照按最新自动音频文档执行。默认/CI 仍为 Mock，本章不因此新增 Provider/TTS、上传控件或公开契约。

## 1. 目标

解决参考图中的关键物品在视频运动过程中被替换、变形或消失的问题。该能力适用于拂尘、剑、书、车辆、产品包装、首饰、徽标、设备和服装配件等对象，不为某一个道具写特例。

## 2. 规则

对象约束按以下优先级合并：用户在故事/想法中的明确说明 > 已确认图片的视觉对象分析 > 通用连续性兜底。用户说明只覆盖冲突字段，不会因为视觉分析缺失而猜测图片角色。

每个关键对象形成内部 `KeyVisualObjectLock`，至少包含名称、外观描述、持有者/空间关系、连续性要求和禁止替换项。对象锁写入每个生成片段的动作计划，并复制到每个 MotionBeat，确保动作变化只改变姿态或位置，不改变对象身份。

提示词顺序固定为：用户创作目标、参考图职责、关键对象正向锁、关键对象禁止替换、动作节拍、一般人物/场景锁。对象锁必须位于风格和一般背景描述之前，并预留固定预算，避免长资料挤掉关键对象。

## 3. 视觉分析

多模态分析器仍只在服务端运行。返回的 `objects` 是安全摘要，不保存原始模型响应、图片 URL、对象 key 或凭据。对象名称和描述限制长度与数量；低置信度对象不得自动成为硬锁，用户明确说明可以提升为锁。

## 4. 质量检查

生成后的技术 QC 之外，后续媒体 QC 应按对象锁抽取关键帧，检查对象是否可见、是否仍由正确主体持有、是否出现明显替换。发现缺失或替换时进入 `NEEDS_ATTENTION`，不能把失败结果标为对象连续性通过。C11.4 本轮先完成对象识别、提示词编译和动作节拍绑定，媒体语义 QC 作为 C12 后续增量保留。

## 5. 兼容和边界

新增字段全部可选并带空数组默认值，历史 MotionPlan、TaskRun 和 PromptPackage 无需迁移。公开 CreativeBrief、Storyboard、TaskRun、SSE 不暴露对象分析正文；对象锁只存在于私有 PromptPackage、动作计划和不可变执行快照。默认 Mock 仍为本地模式，真实 Provider、Veyra、VPS、部署和 Git 写入不属于本设计。

## 6. 验收

- 用户明确写出“手持白色拂尘”时，所有 MotionBeat 都含拂尘正向锁和禁止替换锁。
- 视觉分析返回对象时，Control API 能合并对象锁并编译到真实出站 Prompt。
- 多对象去重、长度/数量预算、历史空字段兼容和 Prompt 顺序有单元/契约回归。
- 未配置视觉分析时，无对象说明的任务继续保持原有安全行为，不按图片位置猜测对象。
