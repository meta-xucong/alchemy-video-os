# AI 企业内容生产平台：长叙事自动编排与连续成片设计

状态：`DESIGN_BASELINE`

关联章节：C10、C11、C12。本文是跨模块总览，不定义前端控件细节、数据库字段或 Worker 实现细节。

平台级编排规则以 `AI企业内容生产平台_通用叙事点与生成片段编排规范.md` 为准。本文只说明长叙事如何应用该通用规则；任何题材、时长或 Provider 都不得绕过“叙事点 → 生成片段 → 最终成片”三层模型。

## 1. 目的

平台面对的用户不应手工把小说情节拆成镜头，也不应把一段长文本直接塞进一次视频请求。目标是让用户在单个项目中提交故事和少量参考素材，先得到可以理解和调整的故事计划，再以明确确认开始多段视频制作，最后得到可追溯的完整成片版本。

正确的主链是：

```text
故事和素材 -> 故事计划 -> 叙事点 -> 生成片段 -> 用户确认制作 -> 分段生成与验收 -> 合成/QC -> 成片版本
```

拆分依据是事件、人物状态、场景变化和节奏，而不是字数、字符数或“每段固定 15 秒”。叙事点数量不等于 Provider 调用数量；多个叙事点可以归入一个满足 Provider 安全时长的生成片段。短想法也走同一条链，只产生一个或少量生成片段；不存在绕过故事计划、把原文直接循环提交给视频 Provider 的路径。

## 2. 当前基线

截至 2026-08-16，当前实现是单项目、单 Shot 的真实视频闭环：项目隔离、参考素材上传和绑定、可调单段规格、生成/重试、恢复、归档和项目内视频版本播放均已有本地验收记录。它不包含自动剧本、自动分镜、多段依赖、连续性 QC、字幕/音频、合成或完整长片。

因此，本设计不改写 C09-C 的行为或声称其已经实现长片制作。ADR-0039 已将真实 Veyra/VPS/其他系统联动后移至 C13-A；缩小范围后的 C09 处于 `READY_FOR_AUDIT`。在 C09 正式 `ACCEPTED` 前，C10/C11/C12 只能维持设计和准备状态。

## 4. 统一产品决策

1. 用户看到的阶段固定为“输入故事、故事计划、制作视频、查看成片”。用户不需要理解 Shot、TaskRun、PromptPackage、ProviderAttempt 或对象存储。
2. 故事计划可自动生成，但计划本身不发起视频 Provider 调用。只有用户点击“开始制作完整视频”才会创建多段视频工作。
3. 每一个生成片段是独立的、不可变输入快照和 TaskRun；叙事点只是故事层事实，不直接创建 TaskRun。整体制作进度另由 ProductionRun 表示，不能把二者混为一个状态机。
4. 单段重做只影响被修改的生成片段和引用它作为连续性前序的后续片段；已验收且不受影响的片段不得重做。
5. 最终成片是新的 VideoVersion，绝不覆盖已有镜头结果或历史成片。
6. 前端显示当前 ProductionRun 的生成片段数量，历史片段数量必须单独标注，不能混在当前计划里。

## 5. 连续性的真实边界

连续性分为三个层级：故事事件连续、画面交接连续和最终成片连续。C11 负责叙事点到生成片段的分组、前两者的计划和依赖，C12 负责从已接受生成片段提取交接帧、做转场/合成和最终 QC。

当前 `aiself-grok` profile 的公开单 Shot 输入模式仍是一张 `FIRST_FRAME` 或一至七张 `REFERENCE_SET`；没有已认证尾帧字段或帧级连续性能力。长叙事 C12 路径采用受控内部策略：前段通过 QC 后抽取交接帧，后段以交接帧作为第 0 位参考输入，并在第 1 位起继续携带用户上传参考图稳定身份、服装和场景。系统必须如实给出“连续性标准”或“需要确认”的计划建议，不得把这一能力表述为模型保证逐帧无缝。

## 6. 交付顺序与门禁

1. 关闭或正式审计当前 C09，保持一次只有一个章节 `IN_PROGRESS`。
2. C10 将上传的长小说、PDF、DOCX 等资料转换为可追溯 Artifact；用户直接粘贴的故事仍直接形成 CreativeBrief，不强制经过文档转换。
3. C11 先实现 revision、故事规划、叙事点/生成片段分组和用户确认，不接入真实视频批量制作；Planner 先以 fixture/fake port 覆盖。
4. C12 再实现按生成片段的交接帧、依赖调度、QC、受控渲染和 VideoVersion。
5. 只有所有离线/Mock 集成测试通过后，才可对经认证的真实 Provider 申请一次有界多段验证。该验证必须单独记录 profile、镜头数、额度上限和素材范围。

## 7. 跨模块验收结论

完成时必须同时满足：长故事按叙事事件形成有序叙事点；叙事点按 Provider 能力和叙事边界形成生成片段；计划确认前零次视频提交；每个生成片段幂等且可恢复；依赖片段被正确阻塞；局部重做不破坏历史；成片可播放、可追溯、可重新合成；当前生成片段数量与真实 TaskRun 数量一致；浏览器永不接触 Provider、密钥、对象 key、签名 URL 或内部任务字段。
