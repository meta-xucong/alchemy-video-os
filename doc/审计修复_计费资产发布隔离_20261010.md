# 计费产物发布隔离：本地审计修复

## 范围与既有依据

本修复以平台代码基线 `44da8428` 为参照，只修正平台资产读取、引用与发布边界，
不改 Provider、扣费金额、扣费协议、状态枚举或公开 DTO。文档修正基线另见 `8ab9862`。
未访问真实 Provider、共享积分服务、VPS 或生产数据。

既有约束来自 `AGENTS.md` §5.2、《AI企业内容生产平台_领域模型与API事件契约》§3.2，
以及《AI企业内容生产平台_Sub2API与Alchemy共享积分适配规范》§6：成功前不发布结果，
扣费失败保留产物用于恢复，但不向普通用户生成下载 URL。

原始平台符号与差异：

- `DrizzleTaskRunRepository.completeGeneratedTaskRun` 与内存同名方法将已验证视频标为
  `Asset.status=READY`，有计费快照时仍保留 `TaskRun.status=BILLING_PENDING` 和空
  `resultAssetId`。保留这个内部字节事实，不新增或重新定义资产状态。
- `DrizzleAssetWorkspaceRepository.findProjectDetail/findAsset`、
  `WorkspaceRepositories.findAsset`、`findTaskRunResultAsset`、参考绑定校验和分镜选择校验
  原先仅检查资产范围或 READY，无法证明扣费完成。新增统一的成功任务归属校验。
- 两种资产仓储的 `confirmAssetUpload` 原先可返回甚至推进服务器生成资产。
  现在新请求及幂等回放均仅接受 `USER_UPLOAD`，不改变普通上传的响应结构。

## 发布规则

只对 `kind=VIDEO && origin=GENERATED` 增加发布门槛：

1. 资产是 READY。
2. `metadata.task_run_id` 指向同 workspace、同 project 的 `VIDEO_GENERATION`。
3. 该任务已经 SUCCEEDED，且 `resultAssetId` 精确指回当前资产。

缺失归属、错误归属、BILLING_PENDING、BILLING_FAILED、RETRY_SCHEDULED 及其他未成功
状态均拒绝。该规则同样覆盖历史已标为 READY 的未扣费产物，无需迁移历史数据。
用户上传、生成音频及 DERIVED 合成视频/交接图沿用已有发布规则，不要求视频任务归属。

`releasedAssetScope` 在持久化公开读取和引用使用之前执行；`isAssetReleased` 提供相同
内存/HTTP 防御。项目详情、任务详情和签名下载均不得提前返回视频产物。
下载路由可读取任务仓储中的已发布结果，使独立保存生成产物的内存实现也能执行相同成功路径。
内部 `ensureGeneratedAsset`、下载草稿查询及计费恢复读取不使用公开发布过滤，避免隔离后无法恢复。

## 回归验证

- `packages/persistence/tests/asset-release.test.ts`：所有非成功任务状态、同工作区/项目/任务/
  结果 ID 绑定、缺失归属、生成音频和 DERIVED 资产兼容，以及 SQL 边界结构。
- `apps/control-api/tests/billing-release.test.ts`：同一组内存/PostgreSQL 生命周期检查，
  从 DOWNLOADING 到 BILLING_PENDING、BILLING_FAILED、RETRY_SCHEDULED，再恢复成功；
  检查项目/任务读取、零次未授权签名、参考复用、分镜选择、上传确认及回放，最终只发布一次。
  另覆盖无计费 Mock 的正常成功。所有计费调用均为仓储级离线 fixture，不调用外部服务。

建议命令（从仓库根目录，先构建依赖）：

```sh
pnpm --filter @alchemy-video/control-api exec tsx --test tests/billing-release.test.ts
```
