## 1. 缺陷与证据

事故 Run `prd_01M4Q2JDY0QKG1TPNNY52081P7` 的三个 TaskRun 均因参考图交付预检失败终止；ProviderAttempt 与 usage 记录均为 0。执行顺序是先 `resolveVisualInput()`（包括 relay 预检），成功后才建立 ProviderAttempt，因此没有发生 Provider 提交或计费。

本地启动器先等待 Control API 健康，再启动 Task Worker；VPS Compose 原先只让 Task Worker 等待迁移、MinIO、Redis，没有等待 Control API readiness。Worker 启动后立即开始恢复和消费队列，因此服务更新时可能在 relay 尚未可用时处理任务。VPS 当前对该失败图片做的内部 Edge→Control API→MinIO HEAD 返回 200，MIME 与长度匹配；这是当前链路证据，不足以复原事故时的具体 HTTP/网络故障。

## 2. 目标和硬约束

1. 真实 Provider Worker 必须在开始恢复/消费队列前，确认配置的 HTTPS `REFERENCE_DELIVERY_ORIGIN` 的 `/provider-input/` 路由已就绪。
2. readiness 探针只能发 HEAD 到固定 origin 下不可用的固定探针路径；只接受 relay 的 `404 + Content-Length: 0 + Cache-Control: no-store`，以免把 Studio fallback 的 HTML 404 误认作就绪。不跟随重定向、不读取对象、不访问 Provider、不创建 TaskRun/ProviderAttempt。
3. readiness 等待有总时限，瞬时错误使用有上限的退避；超时或永久 HTTP 错误时 fail-closed，Worker 不消费队列。
4. Mock Provider 不做公网探测。本地全栈仍按既有顺序启动；真实 Provider 缺失 relay origin 或签名密钥时启动即 fail-closed，不新增 Mock 模式网络依赖。
5. 任务级预检仍在 ProviderAttempt 前执行。预检重试保持有界，并且不得把 URL、token、密钥、图片哈希、资产 ID 或原始网络错误写入日志。
6. 不改变公开错误码、TaskRun/ProviderAttempt 状态、Veyra 扣费时序或已有图片 MIME/尺寸/项目隔离验证。

## 3. 最小实现

- Control API Compose healthcheck 从进程 liveness 改为 `/api/v1/health/ready`（数据库依赖就绪）。
- Task Worker 和 Edge 对 Control API 使用 `service_healthy` 依赖。
- 非 Mock Worker 在 `worker.start()` 和启动恢复之前，通过实际配置的 HTTPS origin 做固定 invalid-token HEAD；只有 404 才放行。重试最多等待 120 秒，使用有界指数退避。其他非瞬时状态 fail-closed。
- 任务级参考图预检把 DNS、TLS、timeout、通用网络、HTTP 状态、MIME、Content-Length、空 body、超限 body 归为安全诊断类别。只在最终失败时写结构化日志，不写请求 URL、HTTP body 或上游原始异常。
- 任务级瞬时重试从短固定等待调整为 1s、2s、4s…有界退避；重试次数仍受现有 `REFERENCE_DELIVERY_PREFLIGHT_RETRIES` 限制（最大 3 次）。

## 4. 测试与放行标准

- readiness：invalid-token 404 放行；503 后恢复为 404 时只进行 HEAD 并有退避；401/200/redirect 等非预期永久响应拒绝启动；等待超时 fail-closed。
- 真实 Provider 模式下显式 `REFERENCE_DELIVERY_PREFLIGHT_ENABLED=false` 必须在 Worker 启动时 fail-closed，不能只通过 relay 启动探针后消费队列。
- OpenSSL `ERR_SSL_*` 与 Node TLS 错误归入 `TLS` 诊断类别；日志不包含上游原始错误。
- readiness 与预检日志：只包含枚举原因、HTTP 状态、尝试次数/耗时和 retryable；不包含 origin、URL、token、密钥、资产 ID、原始异常内容。
- 参考图预检：DNS/TLS/timeout 分类安全；瞬时失败按有界退避重试；结构错误不重试；失败时 Provider submit 和 ProviderAttempt 均为 0。
- Mock Worker 不访问公网；已有参考图映射、HEAD→GET fallback、对象限制和流取消回归继续通过。
- Compose YAML 可解析；Task Worker 等待 Control API `service_healthy`，Edge 不早于 Control API readiness。
- Task Worker build/typecheck/定向测试、相关 Control API health 测试、`git diff --check` 通过。
- VPS 部署只更新 Task Worker 代码/Compose 配置涉及的应用服务；不触碰数据库、Redis、MinIO、Sub2API 配置或卷。部署后验证 Control API readiness、Edge 无效 token HEAD/GET 404、Worker readiness 成功及无 Provider 任务提交。
