## 2. 目标与明确非目标

唯一目标：把当前 G02 实体到参考图 usage 的四项校验失败，映射为可区分的固定诊断码，使下一次获准规划若仍失败时能判断拒绝原因。

本补充只允许内部 `issues[].code` 的诊断精度变化。不得改变任何通过/拒绝条件、顺序、输入、成功产物、用户可见状态或外部调用行为。不得自动修复、降级、增加重试、改写 Brief/usage、接受未绑定素材或放宽 fail-closed。

明确禁止记录或返回：模型原文/响应、提示词、usage 文本、source quote、candidate key/name、asset ID、素材内容、密钥、endpoint、请求/响应正文。诊断只能包含本文列出的固定码。

## 3. 冻结的校验语义与诊断码

当前每个候选实体的每个 `reference_asset_id` 必须同时满足：

1. 冻结 reference 的 `user_declared_usage` 非空；
2. usage 精确提及该 candidate 的 `exact_name`；
3. 同一 usage 字符串存在于该 candidate 的 `source_evidence_refs`；
4. `resolveCandidateEvidence(bundle, usage)` 唯一解析为 `REFERENCE_ASSET`。

分别使用以下固定码：

| 条件失败 | 诊断码 |
|---|---|
| usage 缺失或空字符串 | `G02_REFERENCE_USAGE_MISSING` |
| usage 未精确提及绑定实体名 | `G02_REFERENCE_USAGE_ENTITY_NAME_MISMATCH` |
| usage 不在该候选的 source evidence refs 中 | `G02_REFERENCE_USAGE_NOT_IN_CANDIDATE_EVIDENCE` |
| usage 不能唯一解析为 `REFERENCE_ASSET` | `G02_REFERENCE_USAGE_NOT_REFERENCE_ASSET` |

保持外层 canonicalizer 错误码 `CANONICALIZATION_SEGMENT_SOURCE_SCOPE_INVALID`。旧的 `G02_REFERENCE_USAGE_ENTITY_MISMATCH` 不再作为该分支的输出码；此前已记录的 revision 11 诊断是历史事实，不回写、不改名。

### 3.1 错误收集与失败顺序

- candidate 顺序继续采用输入数组顺序；同一 candidate 内的 reference 顺序继续采用 `reference_asset_ids` 顺序。
- 仅诊断**第一个失败的 reference mapping**。保留原有 candidate/reference fail-fast 顺序；发现首个失败 mapping 后，不再检查后续 mapping。
- 对这个 mapping 收集全部适用 predicate 的固定码，按下表与下方判断顺序输出；同一码只出现一次，然后 fail-closed。
- 对缺失/空 usage，只输出 `G02_REFERENCE_USAGE_MISSING`；其他依赖 usage 内容的判断不适用。
- 对非空 usage，名称匹配、source-evidence membership 和 evidence kind 三项独立判断；可同时返回多个固定码。固定判断顺序为：名称、membership、evidence kind。
- 不输出 reference 序号、候选标识或任何输入值。因此诊断说明“哪些校验维度存在失败”，不声称指出具体素材或逐条映射身份。
- 后续 candidate/reference mapping 不参与本次诊断；不得通过错误消息、code 参数、日志字段或异常对象属性补充输入信息。

本收集仅作用于原有复合拒绝分支。此前校验、候选 fail-fast 边界、该 candidate 不通过即拒绝及之后 canonicalization 均不改变。所有失败 predicate 仍拒绝，不引入宽松或修复路径。

## 6. 测试与放行门

最少要有以下纯 fixture 单测：

1. usage 缺失/空值只得到 `G02_REFERENCE_USAGE_MISSING`；
2. entity name 不匹配只报告对应名称码（其他条件有效）；
3. usage 不在 candidate refs 时报告 membership 码（其他条件有效）；
4. usage 与已存在的 source/decision evidence 形成解析歧义，且 candidate 的其他有效 source evidence 仍能支撑实体名；fixture 不把这个歧义 usage 放进 candidate refs，因此期望同时出现 `G02_REFERENCE_USAGE_NOT_IN_CANDIDATE_EVIDENCE` 与 `G02_REFERENCE_USAGE_NOT_REFERENCE_ASSET`。此组合是可达的：若把歧义 usage 本身放入 candidate refs，更早的候选证据完整性门会先 fail-closed，不能伪造“单独 kind 失败”的测试；
5. 两个以上 predicate 同时失败时，所有适用固定码按规则稳定返回、重复码去重；
6. issues/errors 的可序列化诊断不包含测试 canary 中设置的 usage、source text、candidate name/key、asset ID。
