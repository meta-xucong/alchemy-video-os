# AI 企业内容生产平台：原仓库原则驱动的 4096 UTF-8 保真保护性压缩开发文档

## 1. 窄片范围

本窄片处理 `packages/provider-video/src/runtime-profile.ts` 的
`compactRuntimePrompt`、Provider 编译器调用边界，以及 Workflow → PromptPackage
→ 持久化调度 → Production Worker 快照的内部 sidecar 传递和定向测试。固定的
Huobao、Seedance 和 OpenMontage 来源没有提供通用 Prompt 压缩器；按用户授权，本平台
增加一个最小的 source-first 薄壳：只在编译器明确传入 authored source 与 generated
parts sidecar 时压缩，保留 source，按完整 generated part 逐项省略，不能靠字符串
marker 猜 provenance。

本窄片不修改领域 contracts、公开 HTTP API、Provider 协议、状态账本、真实调用、
网络配置或 Git。新增的 source/parts 信息只通过既有私有
`capabilitySnapshot` JSONB 在内部编译、持久化调度和快照调用之间传递，不新增
公开字段；既有 `SUB2API_GROK_PROFILE_PROMPT_MAX_UTF8_BYTES` 和
`DEFAULT_VIDEO_PROMPT_MAX_UTF8_BYTES` 继续作为 profile/配置事实，不新增阈值。

## 3. 保真压缩规则

1. 先用现有 `TextEncoder` 计算 UTF-8 字节数；低于或等于 ceiling 时直接返回
   原始 `prompt`，包括首尾空白、换行、引号和 `@` anchor。该规则同时适用于
   Mock，不得因为 Mock 而 trim。
2. 超过 ceiling 时，调用方必须同时提供完整 `sourcePrompt` 和按原顺序传入的
   `generatedPromptParts`，且 `[sourcePrompt, ...generatedPromptParts].join(" ")`
   必须逐字等于待压缩 prompt。无法证明这个关系时，继续使用既有
   `UnsupportedVideoGenerationInputError`，不猜测来源。
3. `sourcePrompt` 仍是首要来源。第一轮不改写 source，只按完整 generated part
   省略；如果 source 本身仍超过 ceiling，才进入第二轮。第二轮只删除 runtime
   内置白名单中的完整“可选冗余句”（声音/表演提示、重复的安全或格式化说明），
   不截断、不摘要、不替换成泛化句，也不按长度切半。未命中白名单、无法完整删除
   或删除后仍超限时，继续抛出既有 `PROMPT_BUDGET` 阻断。
4. 省略顺序由编译器写入 `generatedPromptParts` 的既有顺序决定；runtime 不读取
   文本前缀、不按 marker 或本地优先级正则重排。选择时不改变原 part 的相对顺序；
   能放入预算的整块才保留，放不下的整块省略。
5. 不执行全局 normalize whitespace、marker 扫描去重、重排、suffix、摘要或
   UTF-8 截断。没有 sidecar 的 raw source、项目文档和 protected contract 仍然
   fail-closed；这避免把用户文字误判为生成器副本。

## 4. 允许省略的内容边界

本窄片不从字符串猜“重复 block”。Provider 编译器本身知道 source 与三个完整的
derived parts（对象、引用、对白），因此可以把这些 part 作为 sidecar 交给 runtime。
runtime 第一轮只对该 sidecar 进行完整块的预算选择；第二轮只识别固定、可审计的
可选源句白名单，不删除用户对白、动作、场景、对象事实、`@anchor` 或 reference
映射。它仍不认识也不删除用户 source 中的 `AUDIO PRIORITY`、`Dialogue contract`、
`VOICE PERFORMANCE CONTRACT`、`Reference image roles` 等任意字面文本。

native `Character says` 和原始 quoted script 由 source 保留；当 source 仍在预算内、
而完整对白 part 也能放入时，优先保留该 part，否则只省略派生 part，不动 source。
中文换行、ASCII/中文引号、`@anchor` 和 source 顺序不会被压缩器改写。没有 sidecar
或 sidecar 与 prompt 不一致时，即使文本看起来像 compiler wrapper，也直接阻断。

## 5. 验证清单

- ceiling 内的 ASCII、中文、多行 prompt（含 Mock）返回与输入完全相等；
- 超限且没有 source/parts sidecar、sidecar 不一致、未命中可选源句白名单或二次删除
  后仍超限时抛出既有错误；
- source 本身超限但命中白名单时，只删除完整白名单句，保留对白、动作、场景和对象
  事实，并断言 UTF-8 字节数降至 ceiling 内；
- 超限但 source 可容纳时，只省略完整 generated parts，输出保持 UTF-8 ceiling 内；
- 多行原始台词、ASCII 引号、scene/camera/sound/state 顺序和引用映射保持；
- 超限的 raw source、项目文档和未知 marker 没有 sidecar 时仍抛出既有错误；
- 运行 `packages/provider-video/tests/runtime-profile.test.ts` 与该包 typecheck，
  不调用真实 Provider/TTS/网络。

## 6. 当前验收口径

本窄片现在覆盖三条路径：under-ceiling 原样传递、有明确 source/parts sidecar 时的
第一轮 generated-part 省略，以及 source 命中固定白名单时的第二轮完整可选句删除；
sidecar 已从 creative-planning 经既有
`capabilitySnapshot`、持久化 PromptPackage 和生产调度传入 Production Worker/runtime。
它不是通用字符串 dedupe：没有 sidecar 的自动 wrapper 删除仍保持 `BLOCKED`，因此
不会吞掉用户原文。runtime 的提示词预算异常带有仅供内部调度识别的
`PROMPT_BUDGET` discriminant；其它 `UnsupportedVideoGenerationInputError` 不会被
伪装成 4096 超限。

本轮本地证据（窄片定向）：`@alchemy-video/provider-video` 66/66、
`@alchemy-video/creative-planning` 49/49、`@alchemy-video/workflow-worker` 17/17、
`@alchemy-video/production-worker` 72/72；各包 typecheck 与 `git diff --check`
通过。数据库持久化调度行为测试需在本地 `DATABASE_URL` 下复跑；当前代码链路已有
JSON persistence-shaped 跨层 fixture，但不能替代该集成证据。所有已运行测试均为
本地 fixture/mock，未调用真实 Provider/TTS/网络。此前仅 fail-closed 的版本记录由
本版规则 supersede。
