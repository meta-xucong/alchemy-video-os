## 修复目标

1. **扣费前资产发布**：生成视频的公开列表、下载和引用必须以所属任务成功及结果资产匹配为准；不能仅凭存储 READY 状态放行。保留内部扣费恢复读取，兼容既有提前 READY 的记录。
2. **提交结果不确定**：参考现有认证器的提交前持久预留顺序，在 Provider POST 前建立持久认领。认领存在而请求 ID 未落库时，停止自动和显式重复提交；已有请求 ID 继续恢复查询。不得假设上游支持未声明的幂等字段。
3. **登录回调**：保持 Portal 现有跨站表单协议，校验配置的可信 HTTPS Portal Origin；拒绝不可信或缺失来源，防止任意站点替换浏览器登录身份。
4. **SSE 授权有效期**：连接不得超过签名会话有效期；按有限频率复核现有账号授权，取消、过期或授权失败后不再发送数据。
5. **上传边界**：上传签名绑定预留大小；在读取前检查对象元数据，哈希期间限制字节和耗时；避免重复哈希及在数据库事务内进行大对象下载。图片分析需要的第二次读取同样限制字节、时间并响应取消。拒绝对象保留给受控生命周期清理，不自动 DELETE，避免兼容后端忽略条件头而误删有效资产。

## 迁移与运行边界

- 新增 `0027_provider_submission_reservation`：旧记录缺失 Provider 请求 ID 时一律保留提交不确定性，包括真实的提交前失败。这是有意的保守处理，恢复前需核对上游事实，不能清空标记后盲目重试。
- 应先停止旧 Worker，再应用迁移和启用新 Worker；不支持新旧 Worker 混跑。用户允许该迁移所需的短暂停机，但本轮尚未选定或操作运行环境。
- 历史已签发的下载 URL 仍受原到期时间约束；本补丁限制新读取、签名和引用，不撤销外部对象存储已签发 URL。
- SSE 账号授权复核的最长正常间隔为 15 秒，签名会话到期独立关闭连接；本轮没有增加完整会话注销黑名单。
- 被拒绝的旧上传对象可能仍占用存储；清理策略和生产数据核对继续单独验收。
